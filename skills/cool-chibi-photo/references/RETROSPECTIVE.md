# 整体复盘：从“像个小人”到“还原这张照片”

版本：2.2.0，2026-09-17。依据三类真实单人照片的迭代与本地脚本检查；不附带私人原照与完整会话。

## 结论

适合以独立Skill整合进iluluskill。可复用的价值集中在**情境识别、参考分工、分层修改和分开验收**，适用场景是“真实照片＋同款Q版”。它仍需要有图像能力的Agent，不能包装成安装即自动出图的独立软件。

当前成熟度：单人、原背景保留、轻构图优化已跑通；换背景、大幅重构、多人和宠物只有规则设计，不能因提示词写了就算实测完成。

## 1. 实际暴露的问题

| 现象 | 根因 | 现在的规则 |
|---|---|---|
| 小人缩到画宽约10% | 把全部头发、衣服都设为贴纸禁区，只剩角落小空间 | 分开前景保留蒙版与贴纸禁区；先内移，保持可读尺寸 |
| 有参考仍换了一种画风 | 没有实际传入参考，文字里又混入写实和萌系要求 | 引用图片实际进入工具；清楚区分内容、画风和布局 |
| 参考图的站姿、眨眼被复制 | 没分清“画法”和“这张照片的动作” | 原照决定动作表情，参考只锁已认可的角色设计 |
| 改成坐姿后身体越来越长 | 为桌椅和全身展示迁就成人结构 | 弯曲原角色短腿，家具适配人物 |
| 数字上声称比例合格，用户仍不接受 | 用坐姿外框、长发或家具高度代替身体结构 | 以认可的视觉参考校准，不用粗估数值驳回反馈 |
| 有比耶手，却没在工作 | 抓住了孤立手势，忽略电脑与工作手 | 先写情境句，再检查人与物的互动 |
| 手机遮脸的小人没有眼睛 | 将保留局部遮挡过度编译成禁止露眼，遗漏了可见面部和表情的判断 | 逐区域判断遮挡，保留可见五官；授权范围内只对Q版微调遮挡，完整遮挡不强制补眼 |
| 技术通过就宣布成品合格 | 把Alpha、边距、像素检查当成语义验收 | 技术、视觉、用户接受分别记录 |

关键教训：动作不是几个关键词。需要同时保留站坐/身体倾向、两只手分别做什么、腿的关系、视线表情和关键道具。

## 2. 第二类照片验证了什么

测试照片是竹林中“一手举长笋、一手拿蕨叶、一腿屈起”的单人摆姿，使用背景A、构图B。

- 已生成独立Q版，保留举笋、持叶、屈腿及白上衣/红裤的对应关系。
- 适度裁去上方林冠空间，原主体通过非生成式调色和裁切制作底图。
- 合成贴纸约31.8%画宽，右下留出约3.5%短边边距。
- 检查原片哈希、透明Alpha、指定保护区和贴纸范围外的底图一致性。
- Agent已目视检查，**用户最终接受仍未确认**，因此不能标记为“用户认可案例”。
- 这是新内容和动作的测试，但沿用了已选画风参考；还不能证明完全无参考的首跑稳定性。

该测试支持“情境完整＋服饰对应＋分层合成”能迁移到另一张照片，不证明换背景、宠物或大合照同样稳定。

## 3. 背景与重新构图的复盘

旧流程的问题在于把“保留原主体”“不能被贴纸覆盖”“保持背景”“重新构图”混成一组要求。

现在分成三个层次：

1. **背景编辑**：保留整个人物与关键道具的原前景；模型只贡献允许变动的背景。
2. **几何重构**：人物、桌沿、座椅、电脑等关联对象一致变换，检查落点、透视、光线和阴影。
3. **贴纸覆盖**：禁止挡脸、主要手势、道具辨识和互动部位；下方头发/衣服可适度叠放。

仍未实测的重点：
- 清理路人时是否损坏发丝、杯柄和前景边缘。
- 换景后的光源与支撑面是否自然，是否出现“贴上去”的人物。
- 延展画布和移动完整前景组时，蒙版、坐标和接触关系能否正确更新。
- pixel_lock与缩放、旋转、调色冲突时，能否明确缩小操作范围。

详细操作边界只在 [BACKGROUND_COMPOSITION.md](BACKGROUND_COMPOSITION.md) 维护，避免多处规则漂移。

## 4. 哪些做法保留，哪些不固化

**保留：** 原片只读、独立Q版、任务实际提示词记录、局部修改、不可用能力如实说明。

**作为可调起点：** 右下约30%画宽、22%最小可读宽度、3.5%边距、无参考时的头身范围。这些来自目前示例的设计选择，不是所有画幅的通用最优值。

**不推广成默认：** 电脑、裙子、举笋、眯眼、坐姿、特定发型、某位人物的脸。每张重新识别内容，不把一个人的喜好变成所有用户的必选画风。

用户指定的整体改动、尺寸和风格优先于默认。完整全身服从情境与合理结构，不能为了露鞋而改站姿。

## 5. 开源前的实现修正

2.1.1在2.1.0基础上补了两处实际代码边界：

- 布局报告路径也参与输入覆盖检查，防止使用 `--overwrite` 时覆盖同名保护区JSON。
- 安装时排除虚拟环境、环境文件、输入/输出/工作目录和本机维护台账，避免复制本地运行材料。

公开包按清单核对，软件回归与分发完整性检查可离线运行；不携带用户照片或自动调用生图。README清楚区分安装、生成能力和验证覆盖。

## 6. 第三类照片：镜面自拍与局部遮挡

红色楼梯镜面自拍增加了手机遮脸、持包、错步屈腿与倾斜构图。照片底图保留原倾角并非生成式裁切，Q版只保留简化台阶与人物动作。

第一版提示词把遮挡写成“手机盖住眼睛，不要移开露出眼睛”，结果出现缺少可见神态的空脸，同时身体仍偏长。用户明确指出：手机挡脸不应意味着没有眼睛。

第二版缩短躯干和腿，并按用户要求仅在Q版中略移手机/发丝，露出一只合理位置的眼睛，保留另一眼的自然遮挡和自拍姿势。Agent已检查合成图与深浅底透明边缘；用户最终接受仍待确认。这是有参考且经纠错的实测，不是首跑成功率证明。

**2.1.2固化的边界：** 分开“可见但被模型遗漏的五官”“确实被遮住的部位”和“用户允许的插画补全”。不能把这次修正泛化成每张自拍必须露眼，更不能在道具表面画眼或修改真人层。没有自动化测试能替代这个视觉判断。

## 7. 背景保留仍需要光色判断

新反馈指出照片背景也可以有小优化。此前流程对原片保护强调较多，背景A容易被执行成一次全局调色后直接叠Q版，遗漏局部偏色、亮面和抢眼海报对主体的干扰。2.2.0补充“先指出1～3项实际问题，再做相应局部整理”的步骤。

A内允许局部明暗/白平衡/饱和度整理，物体与空间仍保持；删物与换景继续分别属于B/C。背景优化要以同尺寸前后对照证明收益，不能用过度暗角、假散景或重绘人物代替修图。生成模型若改写细节，只取其允许的光色方向，用原片细节完成调整。

## 8. 从背景光色到整图版式

用户又提供竖版、手写短句、少量爱心的效果参考，并说明文字可以每张变化。2.2.0据此增加了按授权比较竖版、在留白分配主句/小字与点缀、装饰层独立制作的流程。单人照不一律裁竖，参考图的文字也不固定成模板。

本次实图采用原片4:5裁切，沿用自拍Q版，另做英文短句和白色线稿点缀；背景只整理光色。参考Q版的眨眼和比耶没有迁入当前自拍动作。Agent已检查，用户接受仍待确认。

这轮说明需要分别提取参考中的画风、构图、装饰和文字机制；用户认可其中一种，不表示允许改变其余照片内容。

## 9. 后续最有价值的验证

| 优先级 | 验证 | 通过条件 |
|---|---|---|
| 1 | 无任何画风参考的新用户首跑 | 情境清楚、比例可接受，不反复索要信息 |
| 2 | 背景B/C＋复杂发丝/关键道具 | 不重画原脸，边缘、透视和接触阴影自然 |
| 3 | 构图C＋前景组移动/延展 | 人物与道具关系保持，保护区坐标同步 |
| 4 | 双人/宠物/密集合照 | 数量、动作关系、服饰或毛色逐个对应 |
| 5 | 用户直接评价 | 分别收集相似度、动作、比例、构图反馈，不只统计是否成功出文件 |

不为增加规则数量而继续堆提示词。下一轮优先用新案例检验已写规则，再根据实际失败修订。
