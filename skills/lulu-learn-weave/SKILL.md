# lulu-learn-weave:成篇(试味出菜)

你负责把拆解层重构为**可回访的资产**,并按去向出发布版。成篇完成的标志:整理版过验收 checklist、(需要时)发布版锁版。

**本 skill 的铁律**:
1. 整理版里每条引文仍然逐字带时间戳,可溯源回真源。
2. 你的推论和讲者的原话**分层标记**,不许混写(「他说的」/「我的推论」/「给你的建议」三层)。
3. 验收 checklist 不过,不许交付——这是防"弱模型跑主脑位质量塌方"的栏杆,一条都不能省。
4. **引号体例**(回核脚本只认「」,体例混用=误报或漏防):逐字引文用「」,转写错误原样保留;概念/立场/标题的命名用『』或加粗,**不打「」**;转述概括不打「」;编者按语放引号外——「原话」(按:…)。引文允许剪头去尾,**中段不许删改、不许把多人的话拼成一句**——顺滑化改写和跨发言拼接都是造假(2026-08-29 全量回核实测:抽查会漏,抚平式改写只有全量脚本能抓住)。

## Phase 1:成篇

输入:全部细拆文件 + 0-入口的产出档位。整理版落 `3-重构/01-<项目名>整理版.md`,骨架:

```markdown
# <项目名>整理版

## ⭐ 五大判断(全场最值钱的)
每条:判断一句话 + 支撑原话(带时间戳) + 为什么值钱一句话

## 议题线(N 条,对应切分段)
每条线:这条线在争什么 → 各方立场 → 落点/未落点

## 观点地图
谁主张什么、谁反对什么、共识边界在哪(全部带出处)

## (可选)用户发言线
用户本人在场发过言 → 单独成线(原话全录已在 2-拆解,这里给脉络)

## 与既有项目的接点
本场内容与用户其他项目/笔记的具体可对接处;没有就写无

## ⚠️ 存疑区
可疑术语候选、未能定字处、真源缺口——存疑标注本身是合格产出
```

**速览模式**(产出档④):只出「五大判断 + 值不值得细做的一句话建议」,不出全篇。

## Phase 2:验收 checklist(显式,逐项打勾后才许交付)

- [ ] 引文脚本全量回核:`python3 scripts/verify_quotes.py --doc <整理版> --source <逐字稿>`,零容忍(❌→回真源核对→修或删;⚠️ 松匹配逐条人工看)
- [ ] 论点忠实度抽查:≥10 条或 10%(取大),对照原话确认没抓歪
- [ ] 五大判断每条有带时间戳的支撑
- [ ] 三层标记(原话/推论/建议)无混写
- [ ] 未知处标「未知」,无脑补填空
- [ ] 数字复核:整理版内出现的一切数字与真源一致(转写连字陷阱:「6、7k」≠「67k」)

## Phase 3:发布(产出档② / 用户要求时)

**Q4(按去向推档位,不让用户从零定义)**:

> **这份发到哪?① 自己看 ② 群里 ③ 公开**(直接回车 = ①)

| 去向 | 默认档位 |
|---|---|
| ① 自己看 | 不脱敏,整理版即终点 |
| ② 群里 | 人名全员代称(字母/单字)、**引文内称呼一并代称**、不留对照表、去录制链接、内部策略段不进 |
| ③ 公开 | ②全部 + 公司/产品可识别信息处理 + 数据模糊化问一遍 |

档位展示给用户改(逐项列出,不说「隐私」这类大词)。执行后**防漏 grep**:列出全部原名及其变体(昵称/简称/拼音)逐一全文检索,零残留才出门。产出 `4-发布/01-<名称>.md`,🔒 锁版——再改用 `_v2` 后缀,不覆盖。
