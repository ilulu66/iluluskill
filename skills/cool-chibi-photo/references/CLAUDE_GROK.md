# Claude分析，Grok手动出图 · 3.0.0-rc.3

Claude负责看图、选路由、整理完整单图提示词和回传检查；用户自己在Grok上传图片、生成并下载。Claude本身不直接生成照片或插画；这里没有Grok API/MCP自动接入，不调用收费API，也不自动上传私人图片。[Claude官方能力说明](https://support.claude.com/en/articles/9002504-can-claude-produce-images)

## 1. 选对Claude安装入口

**Claude Code（终端）**：首次安装照片Skill可用：

    npx -y skills add ilulu66/iluluskill -g --skill cool-chibi-photo --agent claude-code -y

这需要Node.js/npm提供npx。它安装给Claude Code，不是安装到Claude网页、桌面或Grok。已有同名Skill先检查实际目录并备份，再按所用安装方式更新，避免多个活动副本。新会话读取SKILL.md核版本。

**Claude网页/桌面**：下载包含完整cool-chibi-photo文件夹的Skill ZIP，不在网页里运行npx。先在设置启用代码执行/文件创建能力（新界面可能称Create and edit files）；组织账号还需管理员允许Skills。进入：

    Customize > Skills > + > Create skill > Upload a skill

上传ZIP并启用，再在对话中提供原照及实际选中参考。入口名称以当前实际界面为准；这条流程不用本地Python。[Claude官方Skills说明](https://support.claude.com/en/articles/12512180-use-skills-in-claude)

Claude Code也可以只输出纯文本交接，不必运行codex_job.py。该helper的imagegen-request与next_action为Codex内置工具路径，不是Grok API参数，不能直接交给Grok执行。

## 默认参考与入口

说“帮我用这个iluluskill P图”或标准版时，直接按实际图片适配；明确场景版才先三选一“没拍到我／宠物小物互动／人太小替换”，等答复再编译交接，不把默认用法变成必问菜单。

默认画风已随包提供：[lulu-q-style.png](../assets/lulu-q-style.png)。Claude实际查看这张图，默认把它列为Grok需要上传的画风附件，只借画法/线条/阴影/比例，不借Lulu身份、黑衣、长发、闭眼笑或坐姿。用户自己的明确画风优先；只给原照也可用默认，缺本人身份时只补必要本人资料。详细规则与[默认图下载入口](DEFAULT_STYLE.md)同页；仅贴本地路径不算交付了实际附件。

## 2. Claude先把这一张说清楚

让Claude完整读取SKILL.md及当前场景说明，再实际查看原片和本次参考，确认：

- 本张是standard、no_person、pet_object或small_person；位置是corner还是in_scene。
- 谁是主角、穿什么、做什么，与哪个真实对象互动；分开原片事实、用户说明与获准插画设计。
- 每张参考只贡献identity、style、layout或overall的哪些部分；实际给几张就列几张。
- 已有认可画风/本批锁定就沿用，用户说“你决定”就按委托选择。真的拿不准时先展示可读候选，用当前可用原生选择工具或文字选项等待答复；无答复、预选或超时都不自动选第一项。

**门控**：画风仍待选时，不输出可执行生图交接；small_person未获本图/本批删人许可时，只推荐方案，不输出可执行替换提示词。选画风不自动改变衣服、背景、场景或删人授权。

条件齐备后，Claude一次交付两块：

1. **实际附件清单**：图1＝本张原片的实际文件名；图2/图3＝已选参考的实际文件名及用途。若同一图兼任身份和画风，说明范围并只列一次，不虚构第三张。
2. **可复制的完整单图提示词**：替换模板中全部方括号，删除无效段；准确对应附件编号，不用“参考之前那张”或只给看不到的本地路径。未提供身份或衣服信息就先补必要项，不从历史图库猜人。

## 3. 人类Q版与真实玩偶/猫互动：填写模板

下面是假设实际提供三张图的模板，不是本包附有这三张图。Claude应根据本次真实附件填写、删改；只有两张就相应删去图3并重新编号。不要把待填模板说成已可执行的成品提示词。

**附件清单**

| 上传顺序 | 实际文件名（本次填写） | 用途 |
|---|---|---|
| 图1 | [未加Q版的原照文件名] | 当前真实玩偶/猫、物件数量、场景与光线 |
| 图2 | [已选角色身份参考文件名] | 本批指定人类角色的识别特征；不自动借衣服或动作 |
| 图3 | [已选画风参考文件名] | 角色线条、五官概括、比例及描边；不借文案、衣服或背景 |

**完整单图提示词**

    请编辑图1，输出这一张独立成品，不做多图拼贴。
    图1是唯一待编辑原照：[准确描述真实玩偶/猫及所在环境]。
    图2只提供[已选人类角色的身份特征]；图3只提供[明确选定的角色画法、比例、描边范围]。
    图2/图3中的衣服、动作、背景、文字和其他人物，不因作为参考就自动加入图1。

    主体与衣服：加入[已确认数量及角色]的人类Q版。衣服使用[原片可见衣服，或本批明确授权的服装说明]；不沿用未经指定的历史套装。
    情境：[谁在何处，以什么动作，与图1的哪个对象互动]。
    位置与接触：[明确落点与动作，例如在猫旁蹲下，手接触猫背；或坐靠玩偶旁，手与玩偶有自然接触]。
    让角色与原图地面/桌面有支撑，尺度、透视、遮挡、光向与接触阴影一致，不悬空、不穿透、不增加第三只手。

    保留图1里的真实[玩偶/猫]，它的数量、毛纹或材质、形状、姿态和关键配件保持可辨；不要把它也换成卡通对象。
    图1现有真人、其他物件和重要文字保留。本次只是加人类Q版互动，没有删除或替换真人授权。
    已认可角色比例优先，短躯干、短四肢；不为了够到对象、坐满椅子或露全身拉长身体。允许本次选定的半身和自然遮挡。
    描边按所选参考，不强制厚白贴纸边；不要在右下额外复制第二组角色。

    背景默认保持摄影质感与原空间、主要物件；只按本次授权做克制光色整理，不换地点、不整体动漫化。
    装饰：[clean / light_journal / full_journal中本次已选的一项]。
    新文字：[默认不加；若已开启，只写本次明确给定的准确文字]。
    保留本次已确认的画幅与构图，别用装饰遮住脸、手势或互动对象。
    这是参照生成/编辑的视觉效果，不宣称真人、物件或背景逐像素未变；请输出供人工检查的结果。

若用户明确选soft_illustrated，Claude把背景段改成获准的柔和插画质感范围，仍保留原空间与主物件；不能因选了角色画风就顺带改背景。small_person用独立的获准替换提示词，不能在上面“不删真人”的模板里同时叠加删除要求。

## 4. 用户在Grok手动执行，再回传

1. 用户自己打开[grok.com/imagine](https://grok.com/imagine)，登录后寻找当前账号提供的图片编辑/上传入口，选择编辑现有图片。Grok不会通过npx安装本Skill。
2. 按附件清单上传原照和实际选中的参考，检查界面显示顺序；若顺序变化，同步改提示词中的图号。粘贴Claude交付的完整单图提示词，再由用户发起生成。
3. xAI官方说明支持上传图片编辑与多参考；当前入口、可用参考数量、模式、额度或付费要求以账号实际界面为准。本Skill不承诺所有用户免费或同额度；若缺所需多参考入口，回到Claude调整方案，不假装参考已上传。[图片编辑说明](https://x.ai/grok/use-cases/image-editing)、[Imagine Image 2.0说明](https://x.ai/news/grok-imagine-image-2)
4. 用户下载原始结果文件并回传Claude，别只给缩略图或截图。导出若为JPEG/WebP就保留该格式，不能仅改扩展名充当PNG；确需转换时记录真实转换及其影响。
5. Claude同时查看原片、参考和新结果，按QA.md检查身份/服装、数量、比例、动作、接触遮挡、真实对象细节、背景、文字和有无重复角色。有问题就只改相关要求，交付下一版完整提示词，并说明沿用哪些附件。

**检查与边界**：技术文件检查、Claude视觉检查、用户接受分别记录；没有实际运行的格式/像素检查写未检查。下载成功不等于视觉通过；用户没明确接受不记accepted。没有独立base/chibi/decor就明说未提供，不制造空图层。

严格保主体、原像素不变、无损搬运已认可Q版、透明图层都不是本手动流程的自动保证。遇到这些要求，要说明需实际蒙版、原片合成与相应比较；不能只靠一句提示词或服务宣传代替验证。

本版只形成Claude＋Grok手动交接流程并核对官方说明；未完成Claude网页/桌面ZIP安装、Grok实际上传生成和回传检查的端到端实测。Codex已有结果不作为此路径已通过的证据。
