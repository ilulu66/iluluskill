# 验收与回归 · 3.0.0-rc.1

这是本版检查定义，不能当作通过报告。状态依实际操作记录；生成成功、技术检查、Agent目视、Lulu接受分别处理。

## 1. 先注明本次证据类型

| input_kind | 是什么 | 可以证明什么 |
|---|---|---|
| raw_source_regression | 已核对来源的真实未编辑原片重跑 | 本张原片在当前路径的结果；不能外推全批已通过 |
| finished_image_reedit | 对已带Q版/装饰的成品继续编辑 | 本次修改范围；不能冒充未编辑原片的端到端回归 |
| synthetic_software_test | 随机底图、色块、人工蒙版等代码测试 | 脚本行为；不能证明真实人像、互动或画风合格 |

在实际视觉报告中记录 input_kind、source/参考路径与身份、认可范围、实际执行工具、生成或复用范围、未解决问题。私有完整路径放本地 job/qa，不能带入公开分发包。没有所需原片就列缺口，不先擦掉成品角色后冒充原片。

## 2. 所有结果都要看

- 人/宠物数量与身份映射正确；服装来自当前原片或本批明确说明，不套旧粉裙、不固定双人。镜面反射不是新角色。
- scene_intent 可读；关键动作、视线、表情、道具与拿法没有丢。两臂两手，肩肘腕连接合理；不强露被挡住的手，不把眼睛画穿手机。
- 认可角色的设计和比例优先；新设计短身，不为椅子高度、落地或全身展示拉长腿和躯干。自然半身、获准遮挡可以保留。
- 选定 placement 正确；角色及装饰不遮住脸、核心手势、菜品、商品和重要店招。corner 留足边缘；in_scene 允许自然遮挡或经选定构图形成的画面裁切。
- 背景质感与授权一致；photo 不整景卡通化，soft_illustrated 仍保留原空间与关键物件。光向、透视和接触阴影自然，不蓝皮肤、不磨平毛发和玻璃纹理。
- 装饰档正确；新增文字有授权且逐字检查，不编事实；一源图一成品，不把拼图裁小充数、不拿旧图冒充新生成。
- 若声称改善了背景/构图/自然修饰，对照原片说清实际改善和代价；无充分依据可以保持，不能仅凭跑通调色脚本宣称整体美化达标。

## 3. 每条路由的专门检查

| 路由 | 必查 |
|---|---|
| standard | 指定真人/宠物保留，右下仅一组对应Q版，关键原动作与道具可读；严格保护和视觉编辑的结论范围分清 |
| no_person / corner | 纯景仍是主角，角色不喧宾夺主；角色来源明确，未擅加旅伴/票据 |
| no_person / in_scene | 新增角色有落脚/坐靠，空间尺度、前后遮挡、光向与接触成立；没有凭空删除原人 |
| pet_object | 真实猫/壶等按所选方案保留；人类Q版摸猫或趴靠有真实接触和支撑；不把“互动”误做成旁边贴无关图标 |
| small_person | 替换有明确授权，指定真人及必要影像处理干净，其他人保留；无右下重复，背景局部修补合理；参照重绘不冒称原资产无损搬运 |

## 4. 最小实图回归矩阵

| ID | 用例 | 主要失败信号 |
|---|---|---|
| R01 | 清楚人像 standard，电脑前工作且另一手比耶 | 电脑/工作手消失，真人换脸或Q版只剩摆拍手势 |
| R02 | no_person：天空/远景 corner | 错放入无支撑位置，编旅伴，角色盖住景物 |
| R03 | no_person：门口台阶/凳子 in_scene | 仍强制右下，坐空、脚悬、尺度光向不符 |
| R04 | pet_object：本猫＋人类Q版摸猫 | 猫毛纹变样，手未接触或穿透猫背，多手 |
| R05 | pet_object：茶壶旁趴靠 | 玻璃与杯数变样，趴靠悬空，强制露全身而失去互动 |
| R06 | small_person：推荐、获准后替换 | 未获准就删人，角色拉长，其他人误删或角落重复 |
| R07 | 蓝盘章鱼：菜为主，指定角色共同端同款盘 | 章鱼换玩偶/饮料，共同一盘被画成各端一盘 |
| R08 | 已认可角色的局部位置/动作修改 | 比例、服装、背景或文案无故回退；重画后说原样搬运 |

R02和R03同属场景一的不同布局。至少三个新场景各有真实原片结果，才能说已覆盖三场景；完整矩阵通过范围逐项写明。缺原片、缺授权或缺能力只阻塞相关项，不能换成成品擦除或合成图来填“实图通过”。

蓝房子、Delmoondo目前仅能作为入景效果参考，不能据现存成品决定原先有无真人。旧版28项软件测试仍需通过；新增 helper 测试与软件通过不代替本表视觉和用户评价。

## 5. 技术检查的实际边界

- codex_job.py 的 collect 核对源图/参考哈希、结果新旧、PNG结构/块CRC及复制哈希；它不看人物、动作、文字，不解码像素，也不自动判审美通过。
- Alpha/tRNS元数据不证明实际透明面积或白衣/头发边缘合格。真正透明资产需像素解码、深浅底检查；只有确实检查后才记通过。
- visual 整图编辑不证明原主体零重绘或像素不变；“脸看起来相像”不能改记为严格保护通过。
- strict_subject 计划和 chibi.png 只是资产阶段；完成本地底图/蒙版/合成与 verify-lock 后，才按实际保护区、坐标和允许变换报告检验结果。
- 不存在的图层不交空文件。原图只读，修订另存，不覆盖已认可成品。

## 6. 状态与实际视觉报告

计划缺看图或授权时停在 needs_input_review / recommendation_needed，不把它写为生图中。收集结果默认 ready_for_user_review；视觉缺检就 pending，有问题写 needs_revision。用户接受始终 pending，只有用户明确接受后才记 accepted。

visual-review.json 可包含如下字段；仅在实际看过结果后填写观察事实，不复制空白模板冒充已检查：

    input_kind: raw_source_regression / finished_image_reedit / synthetic_software_test
    reviewer: 本次实际执行检查的人或Agent
    reviewed_images: 实际看过的原片、参考、结果路径
    status: pending / checked / needs_revision
    checks: 人物衣服、动作道具、比例、落地遮挡、背景、装饰文字的实际观察
    generated_or_reused: 实际新生成、参照重绘、资产复用及局部改画范围
    limitations: 缺原片、看不清或尚未核验的事项
    user_acceptance: pending

collect 接受并复制实际报告，不自动验证报告内容，也不自动把 checked 等同用户 accepted。本候选在未取得三场景完整实图与用户认可前，保持 rc.1。

## 7. 条件画风选择的检查

- 真有画风不确定、无明确参考/本批锁定且无委托时，先实际查看并展示本次候选，再提原生或文字选项；2～3项标签与真实图对应，不把虚构图当示例。
- style_selection=needed 的计划应是 style_choice_needed，存在 style-picker.json；不存在 imagegen-request.json，未选择时不生图。若尚未看图或替换未获授权，仍先停在相应更早的输入/授权状态，不绕过它们。
- 原生工具不存在时文字照样可以选择；候选不足2张如实说明，不伪造图或凑出固定三种风格。
- 没有明确答复、超时或仅有预选值，仍未完成选择，不能自动取第一项。答复后用 resolved 和新输出目录计划，所选参考需实际传入；未选画风不继续混入。
- 已明确画风、已认可参考、本批锁定不重复问；用户明确“你决定”才用 delegate，并记录实际采用依据。
- 选择前后 scenario、placement、background_render_style、衣服和 replace_real_person 授权不因画风选项自动变化。
- 用户认可单张效果时，记录 acceptance_scope（本图结果/本批画风等具体范围）；不能将所有参考或未来任务标为 accepted。其他图的 user_acceptance 仍按各自实际答复记载。

以上关卡可由软件测试验证“不产请求”等行为；候选是否真实可读、描述是否准确及认可范围仍需实际审阅，不能用代码测试代替。
