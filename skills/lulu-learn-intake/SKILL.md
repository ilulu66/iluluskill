# lulu-learn-intake:收料(采买入库)

你负责把讲座原料变成**只读真源**,并落成标准项目结构。收料完成的标志:真源落盘、0-入口写好、明档可开始读到项目。

**本 skill 的铁律**:
1. `1-原料/` 落盘后一律只读。此后任何环节(校准、拆解、成篇)都不许改它一个字。
2. 逐字稿是机器转写,**有错是常态**——原样保留,不要顺手"修正"(修正是校准层的事,且要留人拍板)。
3. 拿不到的信息写"未知",不脑补。

---

## Phase 0:识别入口(转写源适配器)

收料的架构是**适配器**:流程只认「逐字稿文本」,转写源可插拔。内置源零依赖,可选源**先检测、缺了就引导,绝不假装能拉**。

用户来时判断(能判断就不问):

| 材料 | 通道 | 依赖 |
|---|---|---|
| `meeting.tencent.com/crm/...` 等录制分享链接 | 链接通道(Phase 1A) | 内置,零依赖 |
| "整理 X 月 X 日的讲座"(线下录音在 Get 笔记) | Get 笔记通道(Phase 1D) | 可选:Get 笔记 OpenAPI |
| 音频/视频文件 | 转写通道(Phase 1B) | 可选:外部转写 |
| 现成逐字稿/文字稿(md/txt/docx) | 直入通道(Phase 1C) | 内置,零依赖 |
| "我下周要去听 XX" | 会前模式(Phase 4) | 内置 |

**缺源引导(首跑自检)**:用户的请求指向某个可选源但环境里没有(无 API 配置/无对应 skill)时,不硬撑、不装死,就地引导:
1. 说清这个通道需要什么(如 Get 笔记:App 录音 + 开通 OpenAPI + 配置 API key);
2. 永远给出兜底路:「或者把转写文本直接发我(直入通道),流程一样跑」。

## Phase 1A:链接通道(腾讯会议)

用 `scripts/fetch_tencent_minutes.py` 免登录拉全量逐字稿。工艺要点(脚本已固化,此处防脚本失效时手工重现):

1. 让用户在浏览器开一次分享页,从网络请求抄 `wemeet-cloudrecording-webapi/v1/minutes/detail` 的三个参数:`id`(auth share id)、`meeting_id`、`recording_id`。
2. 首页请求 `fview=1&limit=N&start_pid=0` 只回前 100 段。⚠️ **`start_pid` 增大不起作用,是死胡同**。
3. **真续页**:`pid=<最后一段pid>&fview=0`(去掉 limit/start_pid),一次返回其余全部段落直到 `more=False`。
4. 响应结构:`minutes.paragraphs[].{pid, start_time(ms), sentences[].words[].text, speaker.user_name}`。
5. 输出统一格式:`[HH:MM:SS] 说话人:内容`,一段一行。

产出命名:`逐字稿-<项目名>-<N>段.md`。

## Phase 1B:转写通道(录音/视频文件)

一期不内置转写。告诉用户三条路(按 Lulu 环境优先级):Get 笔记客户端导入(→转完走 1D 拉回)/ 飞书妙记 / whisper 本地,转完回来走直入通道。**不要假装能转写**。

## Phase 1D:Get 笔记通道(线下讲座主入口 · Lulu 环境)

线下讲座用录音笔记服务录音,服务端转写后按日期/标题拉回**原话级转写**:

1. 检测对应录音笔记服务的 API 配置是否在(API key + client id;以你的本地连接器配置文档为准)。不在 → 走 Phase 0 缺源引导。
2. 检索:`list_notes` 按用户给的日期/关键词筛出目标笔记,多条时列标题让用户选(一问,带默认=最新)。
3. 拉取:`/note/detail → data.note.audio.original` 取**原话级转写**。⚠️ 铁律:**AI 智能总结不是逐字稿**,永远取 original,不取 summary。
4. 落盘:统一转成 `[HH:MM:SS] 说话人:内容` 格式(Get 笔记无说话人分离时如实标"未分离",不脑补);命名 `逐字稿-<项目名>-<N>段.md`,🔒 只读。

## Phase 1C:直入通道(现成文字稿)

检查三件事:有没有时间戳、分不分说话人、是不是全场(结尾是否戛然而止)。缺时间戳/说话人要如实告知用户:后续引文回核精度会降级(只能核到字,核不到时间点),问一句要不要继续(默认继续)。

## Phase 2:建 4 层项目

位置按 /lulu-learn 的落盘规则。结构:

```
YYYY!MM!DD 项目名/
├── 0-入口.md          ← 项目门面(下详)
├── 1-原料/            ← 🔒 只读:逐字稿/PPT/讲者材料/官方纪要
├── 2-拆解/            ← 可重生:分段细拆
├── 3-重构/            ← 可重写:整理版等综合产物
├── 4-发布/            ← 锁版:对外版本(改动走 _v2)
└── 9-归档/            ← 旧版废稿
```

`0-入口.md` 必含(2 页内):这是什么(一句话)/关键事实(日期/时长/讲者/场合)/原料清单(带段数字数)/产出预期(等 Q2 答案)/下一步。

## Phase 3:产出定向问(Q2 —— 全系列最重要的一问)

真源落盘后、交回领班前,问:

> **这场你打算怎么用?① 自己复习 ② 要分享出去 ③ 系统学透 ④ 先看值不值得细看**(直接回车 = ①)

答案写进 0-入口的「产出预期」,决定后续流程深度:①→整理版为终点;②→整理版+脱敏发布;③→整理版后进深加工;④→速览模式(decompose 只出议题脉络+weave 只出五判断)。

## Phase 4:会前模式(主题热词表)

用户还没去听。要主题(讲座名/讲者/领域,一句话即可),然后:
1. 检索该主题的领域核心术语/人名/公司/产品/框架名(检索派低配 agent,纳入由你裁决)。
2. 产出「预期词表」50 词上下:`热词表-<项目名>.md`,两列(词 / 一句话它是什么)。
3. 说明用法:听完拿到转写后,与预期词**近音不同形**的转写词自动标可疑——这是校准的 C 级信源,**只提怀疑,不直接改**。
4. 找不到足够资料就如实说找不到,给出实际找到的部分。**禁止编词凑数**。

会前模式产出的热词表放项目 `1-原料/` 旁备用,项目结构可先建好等录音。
