# lulu-learn-decompose:拆解(备菜)

你负责把只读真源拆成**可引用的原子层**。拆解完成的标志:每段细拆落盘、引文全量回核通过、可疑术语候选清单产出。

**本 skill 的铁律**(违反任何一条 = 返工):
1. 引文**逐字**照抄,带时间戳+说话人,并指向真源文件——转写错误也原样保留(修正是校准层的事)。
2. 摘要只当索引,不当依据——需要判断时回原话。
3. 金句按**文本顺序**排,不按重要度排——不让 AI 的重要度判断污染素材层。
4. 未知写未知。真源里没有的,不许出现在拆解里。

---

## Phase 1:议题切分提案(裁决位,Q3)

读真源(长场可跳读:开头、话题切换处、结尾),提出切分方案,**提案必须带依据**:

> 建议切成 N 段:
> A. [00:00–00:42] 核心争点:×××。首句「…」→ 末句「…」
> B. [00:42–01:31] 核心争点:×××。首句「…」→ 末句「…」
> …
> **哪段要合要拆?直接回车 = 按这个切。**

规则:3–6 段为宜;段界优先切在话题切换处而非整点;每段必带时间跨度+核心争点+首尾原话锚点(让用户 10 秒可确认)。**原料里有讲者 PPT/讲义时,其章节结构是现成的切分骨架**——先按它提案,再用实际话题切换微调(Lulu 2026-06 的原创工艺:PPT 双职能之"钉结构")。

**速览模式**(0-入口产出档 = ④):只出这份议题脉络提案+每段 3 行概述,不进 Phase 2,直接交回领班。

## Phase 2:并行细拆

用户确认切分后,**每段派一个低配 agent**(并行),prompt 必须包含:真源文件路径、该段时间范围、四维格式、上面的铁律原文。每段产出 `2-拆解/0N-拆解<段号>-<核心争点>.md`:

```markdown
## 一、议题脉络
- **[时间戳]** 说话人做了什么(一行一事,按时间顺序)

## 二、论点清单
- **说话人 [时间戳]**:论点一句话。原话:「逐字引文」

## 三、硬信息
- 数据、案例、操作步骤、决策链(每条带时间戳)

## 四、分歧
- 谁 vs 谁,争的是什么,各自原话(带时间戳)。没有分歧就写"本段无显性分歧"

## 五、金句(按文本顺序)
- **[时间戳] 说话人**:「逐字引文」
```

「分歧」维度是本流程与摘要工具的分界线——别人吵起来的地方最值钱,认真找;确实没有就如实写无。

## Phase 3:回核 + 建表自举(主脑亲自做,不下放)

1. **引文全量回核**:使用本系列 `lulu-learn-weave/scripts/verify_quotes.py` 对全部细拆文件执行 `python3 <skill-root>/scripts/verify_quotes.py --doc <细拆文件> --source <逐字稿>`(❌ 未命中零容忍:逐条人工核是 agent 抄错还是转写连字差异,修正或删除;⚠️ 松匹配人工过目)。⚠️ 经验:转写会把「6、7k」粘成「67k」之类,不中先怀疑连字,再怀疑 agent。
2. **可疑术语候选清单**:汇集各段里疑似转写错误的专有名词(近音怪词/前后不一致的人名),产出 `2-拆解/00-可疑术语候选.md`(词 / 出现时间戳 / 疑似正确写法 / 依据等级 A–D)。有会前热词表就先比对热词表。**只标候选,不改真源**。
3. 抽查:随机抽 ≥10 条(或 10%,取大)对照原话,验证论点忠实度——引文对不等于论点没抓歪。

## 收尾

汇报:切了几段、各段细拆路径、回核结果(几条全中/几条修正)、可疑术语几个。然后:

> 下一步不确定?回 `/lulu-learn`,领班给你指一个方向。
